✅ 기존 응원이 새 요약 API로 그대로 보임
준비: 시험 기록 2개 · 다른 기록의 기존 응원 10건

✅ 같은 이모지 연속 켜기 2번 → 1개 — 응답 count 1
✅ 켜기 20번 동시 요청 → DB 1행
✅ 이전 방식(뒤집기) 동시 10번 → 중복 없음 — DB 0행
✅ 켜기·끄기 섞어 30번 동시 → 0~1행, 화면 숫자와 DB 일치 — DB 0행 · 요약 0
✅ 응원 취소 → 0개, 한 번 더 취소해도 0개
✅ 취소 후 다시 선택 → 1개
✅ 다른 이모지 각각 선택(👏·💪·🔥 모두 켜짐)
✅ 다른 기록 응원은 따로 집계
✅ 다른 기기 응원 → 2개
✅ 다른 기기가 꺼도 내 응원은 유지
✅ 새로고침 뒤 내 선택 상태 유지 (A 4개 켜짐, B 0개) — A 4 · B 0
✅ 요약 응답에 기기 식별값 없음
✅ 공개 키로 기기 식별값 읽기 차단 (022) — 0행 보임
✅ 공개 키로 직접 응원 넣기 차단 (019) — 42501
✅ on 값이 참/거짓이 아니면 거부
✅ 기기 식별값 형식이 틀리면 거부
✅ 허용되지 않은 이모지 거부
✅ 요약 요청 기록 101개 이상 거부
✅ 전용 헤더 없는 요청 거부(CSRF)
✅ 기존 응원 데이터 유지 (다른 기록의 응원 행 전후 동일) — 10건 → 10건
